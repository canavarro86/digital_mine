# UG Blast Loop — digital_mine

Система управления буровзрывными работами (БВР) подземного рудника: проходка выработок и очистная выемка
по замкнутому циклу «проект → факт → анализ → исправленный проект».

**Термины.** БВР — буровзрывные работы. Паспорт БВР — схема расположения шпуров, зарядов и замедлений для забоя.
Забой — торец выработки, где ведётся проходка. Шпур — короткое отверстие (до ~6 м) под заряд при проходке.
Скважина — длинное отверстие (до десятков метров) при очистной выемке. Веер — ряд скважин в одной плоскости.
Камера — очистной блок, отрабатываемый веерами. ЛНС — линия наименьшего сопротивления (расстояние от заряда до
свободной поверхности). КИШ — коэффициент использования шпура (подвигание / глубина шпура). ВВ — взрывчатое вещество,
СИ — средства инициирования, ЭДД — электронные детонаторы. ПДМ — погрузочно-доставочная машина. ВР — взрывные работы.
CMS — сканирование камеры лазерным сканером. ELOS — средняя глубина перебора стенки камеры, м.
ПШ — полевой штрек, БДО — буро-доставочный орт.

---

## 1. Что это и какую проблему решает

На подземном руднике паспорт БВР составляют один раз, а бурят и заряжают по-разному: шпуры отклоняются, часть не
добурена, порода трещиноватая или обводнённая. Итог — переборы и недоборы сечения, лишняя порода, которую возят и
перерабатывают за деньги, потери руды в камерах, простои буровых и разрыв между инженером, диспетчером, взрывниками и
маркшейдером.

UG Blast Loop связывает все шаги в один цикл:

```
планирование выработок → паспорт → наряд (люди, машины, забои) → бурение → пересчёт паспорта и замедлений по факту →
заряжание → взрыв в окне ВР → уборка, оборка, крепление → маркшейдерская съёмка → анализ (переборы, лишняя порода в $,
ELOS, разубоживание, причины) → правка следующего паспорта
```

Интерфейс и отчёты на трёх языках (ru / en / es), двое часов («время объекта» и «моё»), ИИ-рекомендации по кнопке.

## 2. Возможности по модулям

| Модуль | Что умеет |
|---|---|
| **Рудник и выработки** | 3D-вид рудника. Мастер «Новый горизонт»: примыкание к автоуклону, заезд, ПШ, БДО с шагом, зумпф, ниша, восстающий; продление автоуклона до отметки. Генерация подэтажей, ручное добавление по азимуту/уклону или по точкам, замена планом проектировщиков с отчётом «совпадает / сдвинута / новая / нет в плане». Статусы: запланирована, в проходке, пройдена, законсервирована. |
| **Геология** | Породы: крепость f, UCS (прочность на сжатие), плотность, трещиноватость, RQD, RMR/Q, обводнённость, содержания. Назначение с приоритетом: интервал по пикетам → выработка → камера / 3D-зона → рудник; «свойства в точке» показывают источник значения. |
| **ВВ и СИ** | Библиотека ВВ (эмульсии, АНФО, патронированные) и средств инициирования. Проверка ВВ на интервал: критический диаметр, водоустойчивость (АНФО на обводнённом интервале запрещено, предлагается эмульсия). |
| **Типовые паспорта** | Создание расчётом или вложением PDF/DXF, версии с историей изменений, согласование «Черновик → На согласовании → Утверждён → Архив», назначение на типы выработок и выработки, подбор подходящего типового для забоя. |
| **Паспорт проходки** | Расчёт по Покровскому и Холмбергу для 4 форм сечения, редактор со шпурами, которые перетаскиваются мышью с мгновенным пересчётом, библиотека врубов, контурное взрывание, замедления ЭДД/НСИ, разрез, подписи, экспорт PDF/DXF/CSV. Пересчёт по факту бурения: зоны перегруза и недогруза, рекомендуемые заряды, файл программирования ЭДД. |
| **Веера и поправочные скважины** | Веера по Лангефорсу: восходящие, нисходящие, смешанные; карта распределения энергии, 3D, экспорт для станка. После CMS-съёмки — итоги камеры, поправочные скважины с окупаемостью: «выгодно добрать / оставить». |
| **Флот и модели машин** | Справочник моделей (Epiroc, Sandvik, Normet и др.) с параметрами, единицами и подсказками; «нестандартная установка» с ручными параметрами. У машины — название («Axera №48»), номер (уникален в руднике), параметры с отметкой отличий от модели. Таблица «Типы и работы»: какая машина на какую работу назначается. Паспорт и сечение проверяются по машине: диаметр и длина шпура, габариты, зона обуривания. |
| **Персонал, профессии и допуски** | Справочник профессий с допусками по умолчанию, совмещение профессий, стажёр с наставником. Допуски на машину (тип или модель) и на вид работ: номер документа, даты, скан. Истекает через 14 дней — жёлтый, истёк — красный и не учитывается. Фильтры «Допущен к…», «Истекает в течение N дней», колонка «Может работать на». |
| **Расстановка (наряд)** | Наряд на смену: пустой, копия вчерашнего или предыдущей смены (каждая строка перепроверяется). Назначение «человек → машина → забой → работа»: списки фильтруются по виду работ и машине, допущенные — первыми, недопущенные — серым с причиной. Камера выбирается с направлением бурения: «Камера −225/−200.6 · нисходящие (из БДО −200.6)». Перестановки фиксируются со временем и автором. Табло «Смена сейчас». |
| **Смены и график ВР** | Таблица смен (1–4, начало и конец каждой, через полночь), проверка покрытия суток с точным местом ошибки. Окна ВР по сменам (0, одно или несколько), время проветривания и допуска людей. «Взорван» — только в окне ВР (вне окна — администратор с причиной в журнал); заряжен, а окно прошло — «Ждёт ВР» и алерт; во время ВР людей в забои не назначают. В шапке: «Смена 2 · 08:00–16:00 · ВР в 15:00» и обратный отсчёт. |
| **Рабочий процесс забоя** | Статусы проходки: готов → бурение → обурен → пересчитан → передан взрывникам → принят → заряжен → (ждёт ВР) → взорван → проветривание → уборка → оборка → крепление → съёмка → анализ. Для камер: … → взорван → выпуск → CMS → анализ. Отчёт буровой (файл станка, флешка, планшет), журнал заряжания по шпурам, планшет с офлайн-режимом. |
| **Анализ** | Проходка: КИШ, перебор и недобор по профилям скана, лишняя порода в м³, т и $, «полустаканы», причины с весами (бурение / заряжание / геология). Камеры: ELOS по стенкам, разубоживание, потери, результат в $, причины. |
| **Алерты** | Диспетчеру: буровая свободна раньше конца смены (подбор следующего забоя с учётом окна ВР), машина простаивает, забой ждёт взрывников, нет готовых забоев, нет допуска, машина в ремонте, нет допущенных на модель в смене, взрыв перенесён. Инженеру: низкий КИШ, переборы, ELOS, отклонение бурения, перерасход ВВ, истекающие допуски. Технические: сервис упал, задержка, память, диск. Telegram — по желанию. |
| **Отчёты** | По смене, суткам, месяцу, забою, буровой, человеку; на экране, PDF (ru/en/es), CSV; ZIP отчёта смены для флешки. В отчёте смены — взорвано в окне ВР и перенесено на следующее окно. |
| **ИИ** | Анализ паспорта, цикла, камеры и сводка по руднику: Claude (Anthropic), ChatGPT (OpenAI), DeepSeek или демо-режим без ключа. Предпросмотр стоимости, кэш ответов, месячный бюджет и суточный лимит, применение рекомендаций к паспорту. |
| **Мультиязычность** | Все тексты — в `locales/<язык>.json`; новый язык появляется без правки кода, если положить файл. Нет перевода — английский и запись в лог. |

## 3. Роли и права

Права назначаются ролям; администратор создаёт свои роли из списка прав (например «Взрывник»). Все действия пишутся в журнал аудита.

| Роль | Что может |
|---|---|
| Администратор | Всё: пользователи и роли, системные настройки, ИИ, пульт эмулятора, разрешение взрыва вне окна ВР с причиной |
| Инженер | Рудник и выработки, геология, ВВ, паспорта (создание и утверждение), пересчёт, флот и модели, персонал и допуски, анализ, отчёты, ИИ |
| Диспетчер | Наряд и перестановки, переходы статусов забоя, взрывные статусы, алерты диспетчера; справочники — только просмотр |

Демо-пользователи (пароль при первом входе нужно сменить):

| Логин | Пароль | Роль | Роль в Grafana |
|---|---|---|---|
| `admin` | `as` | Администратор | Admin |
| `engineer` | `en` | Инженер | Editor |
| `dispatcher` | `ds` | Диспетчер | Viewer |

## 4. Архитектура

```
 Браузер ──► 127.0.0.1:9999 ──► k3d serverlb ──► Traefik (Ingress)
                                                   ├── /          → web (React, nginx)  — в т.ч. /console, /tablet
                                                   ├── /api       → api (FastAPI)
                                                   └── /grafana   → Grafana

 api ──HTTP──► calc (расчёты, HPA 1–3) · importer (форматы, облака точек) · analyzer (факт против проекта)
 api ◄──► PostgreSQL (основные данные)        api / importer ◄──► MinIO (файлы)
 api, emulator ──события──► NATS JetStream ──► ingest (HPA 1–3) ──► ClickHouse (аналитика)
 alerts ◄── PostgreSQL, ClickHouse, Prometheus ──► алерты в интерфейсе и Telegram
 emulator ──HTTP──► api (от имени диспетчера, инженера, взрывника, маркшейдера)
 Prometheus ── Grafana ── Loki ◄── Promtail (JSON-логи всех подов)
```

**Сервисы** (`services/`, один образ Python + образ web):

| Сервис | Назначение | Хранилища |
|---|---|---|
| api | REST API, роли (JWT), аудит, миграции Alembic, загрузка рудника, расстановка, рабочий процесс | PostgreSQL, MinIO, NATS |
| calc | паспорта проходки, веера, замедления, поправочные скважины | — |
| importer | DXF, DWG, STR/DTM, CSV, IREDES, облака точек, сетки | — |
| analyzer | КИШ, переборы, лишняя порода, ELOS, разубоживание, потери, причины | — |
| emulator | эмулятор рудника, сценарии нарушений с эталонами, нагрузка для HPA | NATS |
| ingest | NATS JetStream → ClickHouse пакетами | NATS, ClickHouse |
| alerts | правила алертов каждые 30 с, автозакрытие, Telegram | PostgreSQL, ClickHouse, Prometheus |
| web | React SPA | — |

Общие библиотеки: `services/common` (настройки, БД, модели, i18n, шина, безопасность, метрики) и `services/core`
(вся предметная логика без ввода-вывода, тестируется отдельно).

**Данные.** PostgreSQL — пользователи, роли, аудит, рудник, выработки, камеры, геология, ВВ, паспорта с версиями, веера,
флот и модели, персонал и допуски, наряды, забои и события, отчёты бурения, сканы, анализы, алерты, запросы ИИ (сложные
структуры — JSONB). ClickHouse — события, телеметрия, бурение, циклы, камеры, диспетчеризация, ИИ, статусы. MinIO —
исходные файлы импорта, логи станков, облака точек, вложения, сканы допусков. Пакет рудника — `mines/<имя>/`.

**Пространства имён Kubernetes:** `digital-mine` — наши сервисы, PostgreSQL, ClickHouse, MinIO, NATS; `monitoring` —
Prometheus, Grafana, Loki, Promtail; `kube-system` — Traefik, CoreDNS, metrics-server (для HPA).

**Мониторинг.** Каждый сервис отдаёт `/metrics` (запросы, ошибки, время ответа, события, очередь, задержка ingest) и пишет
JSON-логи. 9 дашбордов Grafana: рудник онлайн, проходка, точность бурения, камеры, ВВ, диспетчер, ИИ, платформа, логи.

**Безопасность.** JWT (HS256, 12 ч), пароли — bcrypt, ключи ИИ и токен Telegram — шифрование Fernet; пароли сервисов
генерируются в `.secrets/` (не в git) и попадают в Secret. Сервисы запускаются не от root, порт 9999 и API кластера —
только на 127.0.0.1.

**CI/CD** (GitHub Actions):
* `ci.yml` — на каждый PR и пуш: ruff + pytest в образе сервисов, eslint + tsc + Vitest, helm lint + kubeconform.
* `deploy.yml` — только после зелёного `ci.yml` на пуше в `main` (`workflow_run`, деплоится ровно проверенный коммит;
  красный CI — деплоя нет): сборка образов → GHCR → self-hosted runner → `helm upgrade --install` → проверка
  готовности → `helm rollback` при ошибке. Ручной запуск (`workflow_dispatch`) деплоит `main` без ожидания CI.
  Runner: `bash scripts/runner.sh <токен>` (Docker-контейнер, ServiceAccount с правами только на namespace `digital-mine`).

**Деплой без простоя.** api и web — по 2 пода, RollingUpdate `maxSurge: 1, maxUnavailable: 0` (новый под получает
трафик только после startup- и readiness-проб, старый гасится после), PDB `minAvailable: 1`, `preStop: sleep 10` —
Traefik успевает убрать под из маршрутов до SIGTERM. У calc, importer, analyzer — `preStop: sleep 5` (к ним api ходит
через Service). Диагностика: OOMKilled нет (перезапусков 0, api 122–138 Mi при лимите 320 Mi), uvicorn открывает порт
только после завершения startup, поэтому проба не пропускает неготовый под. Замер: `bash scripts/probe.sh` (опрос
`/api/i18n/languages` и `/` каждые 0,2 с) во время деплоя.

**HPA api.** Request CPU 100m по замеру `kubectl top`: в простое 3–10m на под → 2 реплики; эмулятор ×60 даёт ≈ 600m →
3 реплики. Эмулятор ходит в api без keep-alive, иначе всё его соединение попадает в один под и третья реплика пустует.

## 5. Требования и установка

* Linux, Docker 24+, 8 ГБ ОЗУ (стек занимает ≈ 5 ГБ), 2 ядра, 15 ГБ диска, свободный порт `127.0.0.1:9999`.
* Утилиты k3d, kubectl, helm, helmfile, kubeconform ставятся в `~/.local/bin` командой `make tools` (без sudo).

```bash
git clone git@github.com:canavarro86/digital_mine.git && cd digital_mine
make tools       # утилиты кластера (один раз)
make up          # кластер k3d, инфраструктура, сборка образов, сервисы, пользователи, демо-рудник
make demo        # запустить эмулятор рудника (×60)
```

| Адрес | Что |
|---|---|
| http://127.0.0.1:9999/ | Система |
| http://127.0.0.1:9999/api/docs | Описание API |
| http://127.0.0.1:9999/grafana | Grafana (папка «UG Blast Loop») |
| http://127.0.0.1:9999/console | Пульт эмулятора (только администратор) |
| http://127.0.0.1:9999/tablet | Страница для планшета (работает без сети) |

| Команда | Действие |
|---|---|
| `make up` | Поднять всё (повторный запуск безопасен) |
| `make down` | Удалить кластер, образы проекта, пароли и кэш (резервные копии сохраняются) |
| `make status` | Поды, память, HPA, helm-релизы |
| `make demo` | Запустить эмулятор |
| `make logs s=api` | Логи сервиса |
| `make test` | pytest, Vitest, проверка Helm-чарта |
| `make lint` | ruff, eslint, tsc, helm lint, kubeconform |
| `make build` / `make deploy` | Пересобрать образы / переустановить релизы |
| `make backup` / `make restore b=backups/<папка>` | Резервная копия и восстановление PostgreSQL, ClickHouse, MinIO и пакетов рудника |

Пароли сервисов: `cat .secrets/services.env`. Сброс к чистому состоянию: `make down && make up`.
Демо-рудник генерируется при первом запуске в `mines/default_mine/` (генератор — `services/core/mine_gen.py`).

**Типовые проблемы.** Порт 9999 занят — освободить или задать `HTTP_PORT`. Поды в `Pending`/`OOMKilled` — `make status`,
лимиты в `deploy/values/`. Promtail «too many open files» — увеличить `fs.inotify.max_user_instances`. Нет ответа ИИ —
«Настройки → ИИ»: ключ и бюджет (без ключа работает демо-режим).

## 6. Сценарий демонстрации (10 минут)

1. **Вход и обзор (1 мин).** `admin / as`. Дашборд, двое часов, бейдж смены «Смена 1 · 08:00–20:00 · ВР в 19:00» с отсчётом до ВР. `make demo` — на табло «Смена сейчас» идёт бурение.
2. **Рудник (1 мин).** 3D-вид, «Выработки → Новый горизонт» с предпросмотром.
3. **Паспорт (2 мин).** «Паспорта проходки» → перетащить шпур — показатели пересчитываются; PDF на испанском.
4. **Флот и персонал (1,5 мин).** «Флот → Модели»: Sandvik DD421 (Axera) с подсказками параметров; добавить машину из модели — название «Axera №…». «Персонал»: горнорабочий с допусками «Axera DD421 + Бурение забоя + Вспомогательное оборудование».
5. **Расстановка (1,5 мин).** «Наряд → Назначить»: вид работ «Бурение вееров» — в списке только Simba и камеры с направлением; горнорабочий серым с причиной «нет допуска на Simba E7 C и на Бурение вееров».
6. **Смены и ВР (1 мин).** «Рудник → Смены»: 3 смены, сдвинуть начало второй на 30 мин — «не покрыто 30 мин», «Сохранить» неактивна.
7. **Анализ и алерты (1,5 мин).** Пульт: сценарий «Отклонение шпуров — средне» → в «Анализе» правильная причина. Выключить авто-перестановки → алерт «Буровая свободна раньше конца смены» → «Переставить» (с отметкой, успеют ли до ВР).
8. **ИИ и платформа (0,5 мин).** «Отправить на анализ ИИ» (демо-режим, повтор — из кэша); Grafana «Платформа», нагрузочный сценарий — HPA поднимает копии `ingest` и `calc`.

## 7. Методики расчётов

Формулы реализованы в `services/core/` и покрыты эталонными тестами (`tests/test_calc.py`, `tests/test_scenarios.py`).
Координаты забоя: x — поперёк выработки (0 — ось), y — вверх от почвы, м.

### 7.1. Удельный расход ВВ — методика Покровского

q = q₁ · f_s · v · e · k_d, кг/м³

| Множитель | Формула / значение | Источник |
|---|---|---|
| q₁ | 0,1·f — нормальный удельный расход | Покровский Н. М. «Технология строительства подземных сооружений и шахт» |
| f_s | структура массива: I — 1,1; II — 1,2; III — 1,4; IV — 1,6; V — 2,0 | там же |
| v | 6,5/√S — зажим при одной плоскости обнажения, S — площадь сечения | там же |
| e | 105 / RWS — работоспособность ВВ относительно аммонита 6ЖВ (принято 6ЖВ ≈ 105 % АНФО) | допущение |
| k_d | (36/d)^0,3 — поправка на диаметр, 36 мм — эталон | эмпирическая |

Число шпуров для сравнения: N = 1,27·q·S / (Δ·d²·k_з), Δ — плотность заряжания, кг/м³; d — м; k_з = 0,65.
Эталон: f = 12, категория III, S = 23,11 м², RWS 80 %, d = 45 мм → q = 2,79 кг/м³ (±0,5 %).

### 7.2. Раскладка шпуров — Холмберг (на основе Лангефорса)

* Линейная концентрация: l = Δ·π·d²/4 (наливное ВВ) или масса / длина патрона; s = RWS/100 (относительно АНФО);
  постоянная породы c = 0,30 + 0,0125·f.
* **Прямой вруб:** эквивалентный диаметр холостых φ = D·√n; первая секция a = 1,5φ, W₁ = a·√2;
  l = 55·d·(a/φ)^1,5·(a − φ/2)·(c/0,4)/s. Следующие секции: B = 8,8·10⁻²·√(W·l·s/(d·c)), B ≤ 2W,
  B' = B − F, F = 0,01·H + 0,02 (ошибка забуривания и отклонение), W_n = √2·(B' + W/2). Предельная глубина вруба
  (95 % подвигания): H = 0,15 + 34,1φ − 39,4φ²; не хватает — предупреждение «добавьте холостые».
* **Подошвенные:** B = 0,9·√(l·s/(c̄·f·E/B)), f = 1,45, E/B = 1, c̄ = c + 0,05, минус H·sinγ и F.
* **Отбойные и оконтуривающие:** то же, f = 1,2, E/B = 1,25.
* **Контурные (гладкое взрывание):** E = 15·d, B = E/0,8, l ≤ 90·d²; включается автоматически при трещиноватости ≥ III или кливаже.
* Наклон контурных и подошвенных шпуров γ = 3°. Забойка 10·d (не менее 0,3 м), у врубовых и контурных — не менее 0,5 м.
* **Согласование методик:** если удельный расход по раскладке < 80 % от Покровского, ЛНС и расстояния отбойных,
  подошвенных и контурных шпуров умножаются на k = √(q_раскл / (0,9·q_П)) (до 3 итераций, k ≥ 0,65, вруб не меняется).

### 7.3. Ожидаемый КИШ, замедления, правка

* КИШ: базово 0,92; −0,03 при трещиноватости IV и ещё −0,03 при V; −0,02 на каждый метр глубины сверх 4 м; −0,03
  для наклонных врубов; −0,06 при струях/притоке и неполной водоустойчивости ВВ; −0,02 при f > 15; в пределах 0,80…0,95.
* Замедления: вруб → отбойные (по расстоянию от вруба) → оконтуривающие → контур (от кровли к почве, парами) → подошва.
  ЭДД: вруб — шаг 75 мс; отбойные — max(50 мс; 3·k·B), k = 12 мс/м ЛНС; контур — 100 мс на группу и 25 мс внутри;
  подошва — 100 и 50 мс; минимальный интервал между соседями 8 мс. НСИ: серия MS (25 мс) для вруба, далее LP, до 3 шпуров на ступень.
* При перетаскивании шпура: расстояние до ближайшего соседа против проектной ЛНС группы (< 0,6 — «слишком близко»,
  > 1,35 — «слишком далеко»); заряды врубовых — по фактическому расстоянию до холостого.
* Пересчёт по факту бурения: фактическая ЛНС по концам шпуров; r < 0,8 — перегруз, r > 1,2 — недогруз; рекомендуемая
  концентрация l·clip(r², 0,6…1,4) (контурные — l·clip(r, 0,7…1,2)), не больше l_max, иначе совет «добавить шпур»;
  недобуренные исключаются, КИШ −0,25·(среднее отклонение − 0,1 м); замедления — по фактическим положениям.

### 7.4. Веера

* ЛНС по Лангефорсу: B_max = (d/33)·√(P·s / (c̄·f·E/B)), d — мм, P — плотность заряжания, г/см³, f = 1, E/B = 1,3;
  практическая B = B_max − (2d/1000 + 0,03·min(H, 30)). Эталон: d = 89, P = 1,10, s = 0,8, f = 12 → B_max = 3,14 м.
* Концы скважин по контуру камеры с шагом E = 1,3·B и недобуром 0,7 м; восходящие — через кровлю, нисходящие — через
  почву, смешанные — оба. Незаряжаемая часть у устья: заряд начинается, где расстояние до соседей ≥ k·E (k = 0,5/0,7),
  не менее 1,5 м и не более 0,6 длины.
* Удельный расход, кг/т = заряд веера / (площадь × ЛНС × плотность); энергия — сумма вкладов заряженных интервалов ~ 1/(r² + 0,25).
* Замедления: веер k стартует в (k − 1)·75 мс, внутри — пары от центра через 9 мс. По факту: заблокированные
  скважины исключаются, соседям +10 % заряда.
* Плоскость веера перпендикулярна оси бурового орта; нисходящие веера бурят из верхней выработки камеры, восходящие — из нижней.

### 7.5. Поправочные скважины и окупаемость

Тонны недобора = объём по CMS × плотность; ценность тонны (NSR) = Σ(содержание × цена × извлечение) × NSR-фактор
(золото: г/т ÷ 31,1035 → унции). Затраты = бурение + ВВ и заряжание + простой (метры / скорость + 4 ч + 0,3 ч на
скважину) + откатка и переработка. «Выгодно добрать», если ценность больше затрат.

### 7.6. Анализ «факт против проекта»

* **Проходка:** профили скана → площади перебора и недобора; перебор % = средний перебор / проектная площадь; лишняя
  порода м³ = перебор × подвигание, т = × плотность, $ = т × (вывоз + 2 $/т погрузка) + доп. крепление. КИШ =
  подвигание по скану / средняя длина шпуров. Причины и признаки: отклонение шпуров (> 2 %), недобур (> 4 %),
  обводнённость, трещиноватость (кат. ≥ IV при переборе > 12 %), крупноблочное обрушение, кливаж (асимметрия > 2),
  пропуск контурных, перезаряд (> 8 %); веса нормируются, сумма < 0,15 — «в пределах нормы».
* **Камеры:** ELOS = объём перебора стенки / её площадь; разубоживание = перебор × плотность пустой; потери = недобор ×
  плотность руды; результат $ = ценность руды − затраты на добычу, откатку и переработку разубоживания − ценность потерь.
  Причины: отклонение скважин, пере/недозаряд, заблокированные скважины, слабый висячий бок, ошибки замедлений.
* Критерий качества: на эталонных сценариях эмулятора правильная причина ≥ 80 % (`tests/test_scenarios.py`).

### 7.7. Время работ и смены

* Бурение забоя, ч = метры / (скорость × стрелы) + шпуры × время перестановки / стрелы + время установки (параметры машины).
* Заряжание, ч = масса ВВ / (производительность зарядной машины × 60) + 0,3 ч на установку.
* Смены относятся к дате своего начала; таблица смен покрывает сутки без разрывов и пересечений; окно ВР лежит внутри смены.

## 9. Решения и отступления от стандартных компонентов

| Решение | Причина |
|---|---|
| PostgreSQL — чарт `groundhog2k/postgres` на официальном образе | Bitnami закрыл бесплатные версионированные образы |
| ClickHouse — собственный минимальный чарт (`deploy/charts/clickhouse`, LTS-образ) | Оператор Altinity тяжёл для 8 ГБ; системные логи ClickHouse отключены, пулы урезаны |
| MinIO — официальный чарт с образом сборки из исходников (`pgsty/minio`) | MinIO прекратил публикацию образов |
| Promtail | Объявлен устаревшим в пользу Alloy — заменить при обновлении |
| Один образ для всех Python-сервисов | Экономия диска и времени сборки; сервисы — отдельные Deployment с ресурсами, HPA и метриками |
| LibreDWG собирается из исходников в отдельной стадии Dockerfile | Пакета нет в Debian trixie |
| Загрузка образов в k3d через `docker save \| ctr import` | `k3d image import` падает на многоплатформенных образах при хранилище containerd |
| Prometheus без Alertmanager | Технические алерты считает сервис `alerts` — единая лента и Telegram, экономия памяти |
| Дашборды Grafana — через helmfile, без sidecar | Минус контейнер |
| Время эмулятора реальное, скорость сжимает длительности | Иначе события «из будущего» ломают смены и отчёты; пороги времени в алертах делятся на скорость |
| Камера в эмуляторе отрабатывается одним взрывом всех вееров | Согласованная модель «проект ↔ факт ↔ скан» |
| Параметры моделей машин — из открытых данных Epiroc, Sandvik, Normet, с пометкой «проверить по паспорту машины» | Скорость бурения, время установки и перестановки производители не публикуют — это типовые оценки |
| Допустимые виды работ по типам машин — `config/fleet_types.yaml` + правка в «Флот → Типы и работы» | Меняется без перезапуска |
| «Ждёт ВР» ставит сервис алертов, когда окно ВР закончилось после заряжания | Без отдельного планировщика |
| Запрет назначений во время ВР — на весь рудник; зоны «горизонт» и «взрываемые забои» есть в настройке, но пока действуют как «весь рудник» | Безопасная сторона до реализации зон |
| При обновлении с прежней версии: машины привязываются к моделям по названию, людям выдаются допуски профессии на 30 дней с пометкой «авто»; отчёт — `/migration` | Ничего не теряется, всё выданное автоматически видно и подтверждается вручную |

## 10. Дорожная карта

* Зоны ВР «горизонт» и «только взрываемые забои»; разные графики ВР по участкам и горизонтам, график по дням недели.
* Чтение Datamine при появлении открытого описания формата; онлайн-приём данных станков (IREDES в реальном времени).
* Мобильное приложение для бурильщика и взрывника.
* Несколько рудников в одной установке (SaaS) и разграничение данных между ними.
* Замена Promtail на Grafana Alloy.
